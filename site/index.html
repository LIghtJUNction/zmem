01 / 控制回路

先看压力，再分配余量。

内存用得多很正常。zmem 更关心任务是否正在等待内存，以及下一步动作会带来多少代价。

03 / 明确的职责

把管理能力收在一个地方。

接管交换空间

采用已启用的 zram 与磁盘 Swap。按需扩容，保留磁盘安全余量，在下次开机初始化 zram。

zram / swap lifecycle

给后台明确的预算

用 zmem run 将任务从启动时纳管。压力下限速和有界回收，显式可丢弃任务可以设置硬限额。

cgroup v2 / memory.high

每一步都能解释

读取进程占用、内存压力、压缩数据与决策原因。JSON 输出让 AI 与脚本使用相同的结构化信息。

status / plan / schema

管理器也要克制

无分配策略内核、无第三方 Rust 依赖。常驻路径保持有界，按需查询进程详情。

Rust / no_std policy

内核负责实际分页和最终 OOM 处理。zmem 管理提前调节与任务预算；应用级检查点、通用内存去重与能耗优化仍属于后续研究方向。

04 / 开始使用

先读状态，再让 zmem 接管。

适用于支持 PSI、cgroup v2 与 systemd 的 Linux。安装管理服务需要 root 权限。

从 crates.io 安装
cargo install zmem-manager --locked
zmem doctor
zmem status --json
sudo "$(command -v zmem)" install --replace

下载 Linux x86_64 / ARM64 预编译包 ↗

原位接管，保留恢复入口。

安装器保存原服务与配置，采用现有活动 Swap，并切换内存管理服务。升级或停止 zmem 会保留活动交换区。

sudo zmem rollback恢复先前管理配置
